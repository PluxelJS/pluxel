# Agent 工作流对照研究

状态：尚未开展。统一脚本 SDK、插件控制和维护入口已有正式实现；当前架构见 [Agent Workflow](../AGENT_WORKFLOW.md)、[Plugin Control](../PLUGIN_CONTROL.md)和[工程索引](../README.md)。这里保留对 agent 使用效率的独立研究问题。

## 要回答的问题

在固定模型、固定仓库快照和相同任务下，比较改动前后的文件查阅、API 选择、错误恢复、误操作、完成结果与 token 消耗。类型检查、功能回归或文档缩短各自提供工程证据，效率结论由实际任务对照得到。

## 任务与观察

保留以下八类任务，输入、允许使用的工具和成功条件在运行前固定：

1. 同名插件与 fork 的精确选择、配置和 CAS。
2. 动态安装后发现节点、同步控制材料并调用业务方法。
3. 同一段逻辑用于 Vite 项目执行与 Node 上传执行。
4. HMR 后旧调用证据被拒绝，重新取得当前证据并恢复操作。
5. 提交响应丢失后，用原 receipt 查询已接纳操作。
6. 新增一种 Host 报告分支并同步真实调用方。
7. 自定义 scope 在正常、抛错和取消路径关闭 admission、等待资源释放。
8. 从配置字段定位 Schema、实现、调用方与检查入口。

分别记录结果质量、查阅文件、失败重试、目标选择错误和资源释放情况。实验结果用于判断是否仍需要扩展查询、缓存或生成能力。
