# 消费端市场插件

状态：设计草案，尚未实现。上级：[提案总览](README.md)。
远端访问与缓存由[目录消费](index-protocol.md)维护；本页只确定消费端职责。

## 装配

Market Plugin 是消费端 Pluxel Host 中的普通插件，可以提供可选 Workbench 页面。
它负责检索、详情和版本选择，将安装请求交给显式装配的安装能力，并读取实际执行回执。
市场后台可以单独部署在 Worker，不需要先运行这个 Plugin 或完整 Pluxel 应用。

消费端既可以是本地应用，也可以是远端长驻 Host。浏览器通过应用接口访问；私有市场和 registry 凭据留在 Host。
CLI 可直接使用相同读取协议，不要求存在 Workbench。
初始市场 Plugin 由应用装配提供，避免必须先打开市场才能安装市场自身。

## 市场连接配置

应用配置拥有市场连接：连接名、API base URL 和认证引用；Plugin 与安装能力复用同一输入。
具体 Host schema 待实现时确定，市场 API 地址与 npm registry 地址是不同概念。
一个组织 API 可聚合公共和私有来源，也可以显式配置多个市场。

请求携带已配置连接引用，不让页面任意提供 URL 驱使 Host 转发凭据。
API、认证主体或配置改变后，隔离旧查询与私有缓存；不能把公共同名包当成私有源失败时的替代品。
市场后台的运营配置属于市场发布者，与这里的连接配置分别维护。

## 按需交互

打开页面只取当前市场的一页摘要；详情、版本和 manifest 分别在需要时获取。
搜索由配置的 API 完成，旧查询结果不能覆盖新查询；缓存有容量边界。
多市场先明确选择或分组展示，各自分页，不混合不同相关性排名。

选中发行后，将完整市场引用与来源交给安装能力。页面展示实际的已保存、待应用、已接纳与失败结果，不把下载完成当成运行成功。
停止 Market Plugin 释放自己的请求、缓存句柄与页面资源；已提交的安装操作及已运行插件由各自所有者管理。
网络错误应可见，不能伪装为空市场或悄悄切换来源。

具体 UI、运营 feature 和安装准入交互在底座验证后设计，见[交付顺序](delivery-plan.md#交付顺序)。
