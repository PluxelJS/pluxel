# 市场客户端的剩余设计

状态：市场浏览与安装已整合到 Package Manager；本页保留认证与结果交互的待办。上级：[提案总览](README.md)。

现有可选 `markets` 配置、直接安装、分页浏览、所选 registry、prepare/confirm 与独立 React 组件见 [Package Manager 用法](../../../docs/plugins/package-manager.md)。请求、缓存与安装所有权由[内部设计](../../../plugins/package-manager/DESIGN.md)维护。

## 私有市场访问

Worker 已区分公共与管理员可读来源，并提供独立私源通知凭据。消费端市场 HTTP client 当前只发送公开请求；应用没有普通消费者的私有目录凭据配置。

下一步需要先决定谁可以读取哪些来源，再设计 Host 持有的凭据引用。浏览器只提交已配置连接 ID，不提供任意 URL 或持有上游 token；认证主体或连接变化时撤回旧请求并隔离缓存。普通浏览权限不能通过分发管理员 token 实现。

registry/auth/proxy 的安装配置继续沿用 pnpm 原生入口。现有安装准备已经核对市场来源与 pnpm scoped/default registry；新增市场认证与 registry 下载认证各有作用范围，不能把市场返回的 URL 变成转发凭据的授权。

## 后续交互

现有目录支持多个配置连接及来源选择。以下交互取决于相应服务先提供结果：

- [自动收录](index-production.md)完成后，显示所选发行的已验证仓库、commit 与构建信息。
- [目录状态](index-protocol.md#版本选择与新鲜度)补齐后，区分未验证候选、来源失败与确认撤回。
- [Host 影响预检](installation.md#安装与升级的预检)完成后，展示全包定义、依赖与运行状态的变化，并在确认时处理失效前提。
- 若需要断线或进程重启后跟踪安装，读取同一持久操作回执。当前候选仅在 store 内存中保留，不能把它当作跨进程任务。

页面继续投影所属服务的结果，不自行维护 Host 运行依赖图。准备阶段可能执行显式获准的构建脚本，确认阶段才发布已有候选；UI 必须清楚表达这两个阶段的副作用。

## 验收条件

用一个公共来源和一个受保护来源验证浏览权限、同名包隔离及原生 pnpm 获取，确认切换主体后旧响应不能进入当前页面。安装结果交互要能区分 wrapper 发布、待新进程生效、实际接纳与启动失败。
