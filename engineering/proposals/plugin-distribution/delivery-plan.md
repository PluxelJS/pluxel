# 交付与验收

当前部署与用法见 [Worker 项目](../../../projects/plugin-market/README.md)。其他设计入口见[提案总览](README.md)。

## 市场部署

- 在真实 Worker + D1 目标环境应用迁移，验证目录读取、写入条件、快照大小与执行成本。执行包含人工编辑、发行和待办的备份恢复，确认旧编辑版本和租约失效。
- 在镜像部署目标对比网页和 Workbench 的搜索、分面、分页和精确发行。按目标同步频率测量主站提交到镜像可读的耗时，以及 D1 查询、传输和导入开销。中断同步时核对旧版仍可读，恢复后核对最新目录与可见性。
- 在目标使用网络完成一次安装，验证区域市场端点、pnpm registry 与发行摘要。目录同步与 npm 制品获取是两条独立链路。

目标 D1 部署、备份恢复和区域网络安装仍待验收。普通回归和本地 PNPR 体验的适用范围见 [Worker 项目](../../../projects/plugin-market/README.md)与 [PNPR 体验指南](../../../docs/development/plugin-market.md)。

## 分阶段验证

| 路径             | 完成条件                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 原生 provenance  | 相同真实样本在目标 workerd 通过；包名、版本、tarball 和签名篡改被拒绝；部署方拥有可信材料刷新       |
| 自动通知收录     | 真实 Plugin 从 registry 拉取并验证，只有有效租约能原子提交目录和成功回执；重试保留既有结果          |
| 新发布 manifest  | 一个通用插件和一个项目专属插件经标准 build/pack 生成；exports、依赖、资源和摘要与 tarball 一致      |
| 项目与 Host 消费 | 同一 tarball 搬离 workspace 后可消费；Host 预检覆盖多 Plugin、provider 与来源冲突，确认拒绝过期前提 |
| 持续扫描         | 第二轮复用未变观测；通知与复核都有预算，超限单包不会阻塞其他工作，进度可恢复                        |
| 管理界面         | 真实编辑、并发冲突和通知诊断由同一 API 完成；旧客户端在写入前被拒绝                                 |
| 私有市场消费     | 普通读取权限和管理权限分开；切换主体、市场与来源时请求和缓存隔离                                    |

失败场景由各设计页维护，包括[目录生产](index-production.md#提交与恢复)、[目录状态](index-protocol.md#版本选择与新鲜度)、[安装预检](installation.md#安装与升级的预检)及[主站恢复](foundation.md#保留与恢复)。
