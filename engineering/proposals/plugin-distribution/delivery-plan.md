# 剩余设计与验证顺序

状态：市场底座与客户端已实现，以下为未完成路径。上级：[提案总览](README.md)。

当前支持范围由 [Worker 项目](../../../projects/plugin-market/README.md)、[插件用法](../../../docs/plugins/package-manager.md)和 [Package Manager 设计](../../../plugins/package-manager/DESIGN.md)维护。技术选型、基本 schema、公开 HTTP、管理条件编辑、来源隔离和安装准备无需重新作为待实施阶段。

## 开始实施的范围

下一轮先选一条明确的使用路径：

1. 可信自动收录：先解决原生 Sigstore/workerd 与可信材料维护，再连接通知到目录提交。
2. Host 升级预检：先确定 Host 提供哪些影响与状态版本，再扩展已有 prepare/confirm。
3. 运营管理页面：使用现有管理 API 完成编辑和诊断，不等待自动收录或新 manifest。

新 manifest 应从具体消费者所需的静态事实开始。它可与验证运行环境分开研究，只有可靠生产并验证所需字段后才进入正式发布格式。

## 分阶段验证

| 路径             | 完成条件                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 原生 provenance  | 相同真实样本在目标 workerd 通过；包名、版本、tarball 和签名篡改被拒绝；部署方拥有可信材料刷新       |
| 自动通知收录     | 真实 Plugin 从 registry 拉取并验证，只有有效租约能原子提交目录和成功回执；重试保留既有结果          |
| 新发布 manifest  | 一个通用插件和一个项目专属插件经标准 build/pack 生成；exports、依赖、资源和摘要与 tarball 一致      |
| 项目与 Host 消费 | 同一 tarball 搬离 workspace 后可消费；Host 预检覆盖多 Plugin、provider 与来源冲突，确认拒绝过期前提 |
| 持续扫描         | 第二轮复用未变观测；通知与复核都有预算，超限单包不会阻塞其他工作，进度可恢复                        |
| 管理界面         | 真实编辑、并发冲突和通知诊断由同一 API 完成；旧客户端在写入前被拒绝                                 |
| 私有市场消费     | 普通读取权限和管理权限分开；切换主体、市场与来源时请求和缓存隔离                                    |
| 目标部署与恢复   | 在目标 D1 验证容量、迁移、查询与并发，恢复后旧编辑版本和租约失效                                    |

这些条件是待完成的验证，不是本轮清理执行过的测试。普通本地 workerd/D1 回归和真实 PNPR 构建发布路径分别见所属项目文档，Sigstore 阻塞保留在[独立实验](../../spikes/plugin-market-worker/README.md)。

## 优先验证的失败场景

| 场景                                      | 要观察的结果                                                  |
| ----------------------------------------- | ------------------------------------------------------------- |
| npm 发布成功、通知响应丢失；证明稍后可读  | 查询或复用原坐标回执，补验同一发行，不重复 npm 发布或伪报收录 |
| 校验完成前租约已过期                      | 发行和成功回执均不能由旧处理者提交                            |
| tag 移到未收录版本，随后来源超时          | 保留真实 tag、已有可选版本和观测时间，不换成旧版 latest       |
| 两个来源提供同名包，升级包内有多个 Plugin | 来源明确，Host 身份冲突可见，影响覆盖整个包与相关节点         |
| 预检后 Host 变化；新代 init 失败          | 失效前提被拒绝；已进入接纳的失败按实际阶段报告                |
| 超限制品与持续通知并存                    | 超限工作结束，其余通知与已知包复核继续推进                    |
| 数据库回退，旧客户端仍持有 revision/租约  | 旧操作不能写入恢复后的状态，无法确认的结果不自动重放          |

## 交付顺序

按实际需求选择一条路径完成，再将实现和用户行为迁入正式文档。自动收录不能绕过原生证明门槛；Host 预检不能由页面推测运行图；管理界面可独立复用已实现 API。

ban、重定向、安装时在线准入、离线授权及多市场政策冲突保持未决。隐藏和分类已经有明确实现，不由这些能力自动推导更广的安装政策。
