# 安装与生效的边界

状态：设计草案，尚未实现。上级：[提案总览](README.md)。
本页保留项目依赖和长驻 Host 共用的职责；本轮先设计市场底座，暂不冻结安装流程与 API。

## 跨 registry 获取

安装编排接收市场返回的精确发行记录，不承担候选发现或扫描。
获取层仍需 registry 来源、包名、版本、tarball URL、integrity 和本地认证；“不绑定 registry”表示来源可变，而不是丢弃来源。
同一安装可以涉及公共与私有 registry，不要求先把所有包镜像到一个自定义 registry。

同名同版不能证明相同制品。市场选择、原生 registry 配置和实际获取结果冲突时要明确报告，不能默默换源。
凭据由部署方按目标绑定，不能通过市场返回任意 URL 就向其转发认证。

## 插件依赖与普通 npm 依赖

| 依赖                        | 职责                                                     |
| --------------------------- | -------------------------------------------------------- |
| Plugin 与 required provider | 使用静态声明确定插件关系，再核对来源、版本和目标 Host    |
| optional provider           | 按实际选择与可用能力参与，不因市场中存在就自动启用       |
| 宿主共享框架或服务          | 核对真实装配和模块身份；安装第二份包不能伪装满足共享要求 |
| 普通实现依赖                | 保留 npm 原生求解与锁定语义，不要求所有库都收录为插件    |

建议先选一个成熟获取/解析引擎，验证真实多来源依赖和 peer context，再确定安装 API。
只向命令传顶层 tarball URL 不能证明所有传递依赖来源正确；不能把所有 peer 都当成 Plugin。
来源、精确字节和原生依赖关系应保留在可追溯安装结果中，不手写另一套与包管理器竞争的通用锁格式。
原生依据见 [npm lockfile](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/) 与 [pacote](https://github.com/npm/pacote)。

远程安装支持哪些依赖来源、如何控制 scripts、何时检查运营规则，属于后续安装设计。
项目直接执行的原生包管理器命令可能已经运行脚本，之后的插件检查不能追溯性地保证此前没有执行代码。

## 两种消费方式

| 消费方式  | 安装结果                       | 生效所有者           |
| --------- | ------------------------------ | -------------------- |
| 项目依赖  | 项目依赖与锁文件变更           | 项目构建、装配与部署 |
| 长驻 Host | 独立托管环境中的制品与持久选择 | Host 接纳及其执行器  |

同一 tarball 和[发布格式](package-format.md)供两者消费，来源完整性与兼容事实保持相同。
项目安装应保留可审查变更；后续构建失败不意味着依赖变更从未发生。
Host 在线安装避免修改运行框架自身的依赖，保存制品与选择也不等于实际启用。

执行器支持 live 时可请求接纳；需要新进程时明确报告待重启。实际能力遵循[当前动态来源](../../../docs/host/configuration.md#动态来源)。
运行身份仍使用[公开入口与具名导出](../../PLUGIN_IDENTITY.md)，不能把版本路径或市场显示名变成 Plugin identity。

## 运行与结果所有权

安装领域拥有获取、校验、制品保留和安装选择；Host/Core 拥有配置、启用意图、接纳和运行事实。
Market Plugin 只是入口，不通过界面状态制造运行成功。

准备失败、已保存但未应用、旧代已停止而新代启动失败，必须分别表达；生命周期依据见[现有语义](../../CORE_LIFECYCLE_SEMANTICS.md)。
脚本、初始化和外部数据写入不天然可回滚，安装不能宣称是跨文件、进程与外部服务的原子事务。
共享 provider、更新影响、旧制品清理与卸载数据边界，在真实项目和 Host 路径验证时细化。

是否需要在线 admission、如何恢复已有部署以及 ban 的作用范围，留给后续明确需求。
市场底座只提供可按需获得、可校验、来源明确的发行事实，不预先把所有安装绑定到某个政策服务。
