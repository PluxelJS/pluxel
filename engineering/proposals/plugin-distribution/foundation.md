# 市场运行与恢复

## 主站与只读镜像

主站以 Cloudflare Worker + D1 运行。D1 保存当前目录、已检查发行、运营编辑和通知回执。包按 `registry + name` 标识，发行再加精确 `version`。同一发行只能接受一个摘要，目录变更和相关审计在同一事务提交。

`GET /v1/snapshot` 在一次 D1 批次中读取匿名可见的包、对应作者和已检查发行，导出有界的整版快照。部署方安排同步，镜像在本地 SQLite 事务内切换完整目录。运行中的镜像始终读取最后一次成功提交的数据，主站断线后继续提供查询，恢复后直接取得最新快照。隐藏与来源范围变更随下一次成功同步生效。 [部署步骤与接口](../../../projects/plugin-market/README.md#只读镜像)

## 同步成本与新鲜度

主站导出后按正文计算 ETag，`304` 节省传输和镜像导入。同步频率由部署方按目录新鲜度和主站开销决定。若实测发现版本检查的 D1 读取成本过高，优先降低条件请求的开销。若整版传输或导入成为瓶颈，再评估增量分发。

镜像只消费公开目录的当前状态。历史回放与批量分析等后续用途，需要先确定要保留的事实，再选择存储和消费方式。

## 保留与恢复

主站 D1 保有 registry 无法完整重建的运营记录、发行摘要和通知回执。镜像目录可以从快照重建，主站备份需要保存完整 D1 状态。

- 主站恢复应保留已确认的发行摘要，保证同一 `registry + name + version` 始终对应已确认的字节。
- 在暂停写入与调度的维护窗口恢复。重新开放前，验证恢复前的编辑版本和任务租约已失效。
- 说明恢复时间和操作范围，把查不到的较新操作报告为无法确认。回执过期和恢复丢失分别表达。

仍需在目标 D1 测量查询、写入、快照大小与 Worker 执行成本，并演练包含人工编辑、发行和待办的备份恢复。部署方据此确定主站的保留期和恢复步骤。验证入口见[交付与验收](delivery-plan.md#市场部署)。

## 目录如何增量提交

人工刷新原子保存发行、观测与审计。后续自动收录应在同一条件提交中核对有效租约，保存发行和完成进度。网络读取与制品校验在事务外执行。每次提交有界的包更新，依据观测时使用的输入版本与时间拒绝过期写入。调度与预算见[目录生产](index-production.md)。
