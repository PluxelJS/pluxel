# 市场管理的后续需求

部署方已可通过脚本调用 `MarketAdmin` 观测包、刷新发行、带 revision 编辑目录，以及查询和重试通知。公开网页用于浏览目录。[管理用法](../../../projects/plugin-market/README.md#市场管理) · [现有 API](../../../projects/plugin-market/src/admin.ts)

## 运营编辑

当运营人员需要在浏览器内处理这些任务时，首个场景可选为修改一个包的分类。页面读取当前记录，按 revision 保存。并发编辑发生冲突时保留本地输入，显示最新记录，由操作者决定如何合并。页面可直接调用现有 Cap’n Web HTTP batch API，并随 Worker 静态资源交付。

验收时由脚本和网页同时编辑同一条记录，核对只有一个写入按原 revision 成功。若还需要从页面重试通知，沿用通知的回执查询处理结果。普通用户读取私有来源所需的权限另由[客户端设计](market-client.md#私有市场访问)维护。

## 客户端与后台任务

- 当客户端独立发布时，再确定可导入的管理契约与输入校验。协议版本用于识别兼容的操作，记录 revision 用于判断编辑的基线。不兼容的旧客户端应在写入前收到明确错误并保留编辑内容。
- `observe`、`refresh` 和 `refreshRepository` 目前在调用内执行。如果实际刷新耗时需要跨断线跟踪，再设计持久回执。提交响应丢失后，同一主体可按原请求标识查询。相同请求重试应返回原结果，标识相同而内容改变时应拒绝。回执过期、客户端停止等待和任务完成须能分别判定。
