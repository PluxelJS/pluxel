# Agent 执行与控制的后续方向

当前 SDK、Node/Vite 执行、插件实例借用和材料同步见 [Agent Workflow](../AGENT_WORKFLOW.md)与 [Plugin Control](../PLUGIN_CONTROL.md)，公开调用见[自动化脚本](../../docs/development/scripts.md)。以下能力尚未完整交付，分别由真实调用方和部署验收推进。

## Cloudflare 执行后端

已有 workerd 实验在 Dynamic Worker 中运行脚本工厂，经 Workers RPC 向原 Host 读取配置和提交条件写入。Host 拥有配置、生命周期与存储。[实验覆盖范围](../AGENT_WORKFLOW.md#workers-的当前证据)

首个部署场景限于一次请求。用当前 SDK 完成读配置、条件写入及核对实际采用，在目标环境检查授权撤回、取消传播、在途调用排空、能力桥释放和 `ScriptError` 映射。需要持久化的应用另用所选存储验证提交和重开行为。[跨 isolate 的可写状态](PLATFORM_NEUTRAL_RUNTIME.md#跨-isolate-的可写状态)

后端明确 run owner、超时、授权撤回和查询寿命。请求拥有的执行随请求寿命撤回；跨断线执行需要可路由到原操作的稳定 owner，例如 Durable Object。持久身份、重复提交与结果保留一起设计。

`describe.capabilities` 只声明实际提供的能力。管理可经授权桥调用；同进程 `plugin.instance()` 借用真实实例。跨 isolate 的业务调用需显式异步接口，分别定义取消、资源句柄、授权和 provider drain。

## 远程 Vite 入口

当调用方需要从另一台机器运行目标项目中已有的脚本时，远程入口可沿用目标 Vite 的项目加载器。拟由客户端选择已获开发权限的实例，提交相对于目标 Vite root 的脚本路径、导出名和已审阅的入口源码 SHA-256。目标核对入口的真实路径与字节摘要，依赖由该实例的 Vite 模块图解析。找不到文件、路径越界或入口已变时，在调用导出函数前报告失败。[现有源码接纳与加载规则](../DEV_CONSOLE.md#提交与执行)

验收时将同一项目放在两台机器的不同绝对路径，分别验证成功执行和目标入口已修改的结果。客户端在发送前保存 receipt，提交响应丢失后凭原 receipt 重新认证并查询原实例。原实例退出时报告原运行无法恢复。若多人还需要远程控制 HMR，再明确谁可以暂停、应用和恢复更新。[执行身份与回执](../AGENT_WORKFLOW.md#运行身份失败和预算)

## 离线配置校验

需要在启动 Host 前检查配置时，先确认部署环境能取得哪些 Plugin 定义、原始配置和环境输入。若目标环境能加载原 Schema，直接复用它。若交付流程需要独立制品，再评估从原 Schema 生成 validator。用相同输入比对离线结果与 Host 对完整配置的校验，缺少动态定义、环境或 Schema 时列出未校验的节点和原因。依赖网络或凭据的检查由获授权的部署环境显式执行，回执展示引用及可用性。

部署变量与 Vault 记录的绑定和启动错误由 [Host 配置指南](../../docs/host/configuration.md#部署凭据与-vault-绑定)维护。

## 控制材料的维护

当前可显式清理废弃目录。若旧快照的占用需要自动回收，先证明哪些快照仍由已导入的脚本或活动编译引用。外部类型依赖由脚本作者提供匹配版本。出现可复现的版本不符案例后，再决定同步时需要核对哪些声明。[控制材料同步与依赖](../../docs/development/plugin-control.md)

当较大目录出现多个同名业务方法、需要决定是否调整控制索引时，再用动态发现任务做对照。两组使用同一模型、材料快照、题目和工具预算，仅改变索引可见性，各用独立会话重复。由实际 Host 核对选中的节点和调用结果，再比较查询次数、重试和 token。[首轮对照与回放](../records/agent-control-evaluation/README.md)
