# 插件控制的后续方向

插件描述符、class 成员声明、配置源码描述、Host 实例视图、Rolldown 构建和材料同步已进入正式实现。当前使用方式见[插件控制指南](../../../docs/development/plugin-control.md)，内部边界和测试入口见[Plugin Control](../../PLUGIN_CONTROL.md)。旧设计和实施顺序由 Git 保存。

后续按实际调用方推进以下独立能力：

- 跨 isolate 业务 API 需要显式异步投影，定义取消、资源句柄、授权撤回和 provider drain。完整 class 类型不能直接成为通用 RPC 接口。
- 离线配置校验需要可独立求值的 validator 制品，明确动态环境、网络检查和凭据的输入。当前配置源码类型用于理解与静态检查，真实校验仍在 Host。
- 持久任务需要可恢复的 run owner、去重身份和结果查询寿命，与现有进程内 receipt 分开设计。
- 不可变材料快照的自动清理需要实际导入与活动编译的保留依据；当前由显式维护清理废弃生成目录。
- 作者侧外部类型依赖的版本和声明指纹核验需要独立的环境契约；当前同步只验证交付材料，原包及公开类型依赖由作者提供匹配版本。

这些能力的完成条件包含真实部署与资源释放，分别进入[脚本后续方向](../AGENT_WORKFLOW.md)。
