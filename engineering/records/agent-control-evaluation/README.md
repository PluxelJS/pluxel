# 控制材料索引的三项任务对照

2026-11-24，六个独立 Codex 会话分别处理三个任务。六份初次答案都通过。动态发现与 HMR 恢复中，原材料组各查询五次，索引组各查询三次。已知配置字段名时，两组都搜索原声明，两次查询就找到了 Schema。

## 任务和评分

临时 Vite Host 有三个名为 `Router` 的定义，分别位于 `standard`、`secondary`、`priority` 源码入口。宿主先启动前两个，再经受控 HMR 新增并接纳 priority，随后更换其业务方法并重新同步材料。每个试验只给模型该任务对应的材料。脚本用生成的 descriptor 借用当前运行实例，判定由实际 Host 的脚本类型检查和执行返回值完成。两组任务文本、脚本示例和评分条件相同。[完整题目、答案与逐次查询](observations.json) · [可执行评分](replay.mjs)

| 任务     | 输入与通过条件                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 动态发现 | 根据“估算优先工单处理时间”选中新增定义，在默认节点上按 `tickets=4`、`rate=3` 调用业务方法，返回 19。fixture 通过添加动态来源文件完成接纳。                               |
| HMR 恢复 | 已知旧脚本调用 `estimateDispatch` 得到 `control_contract_mismatch`。用本次接纳后同步的描述符和当前方法重建调用，返回 119。评分还会用旧材料在新 generation 上重现原错误。 |
| 定位配置 | 从字段名 `shardBudget` 指出原作者文件 `policy.ts`、Schema `DispatchPolicy`、默认值 7 及整数闭区间 2 至 12。                                                              |

## 观察

A 组能列出、搜索、读取两组共有的材料文件。B 组额外能读 catalog、按成员查询签名和导入、按引用查询配置。后两项直接调用 `openControl` 的 `inspectPlugin` 和 `inspectConfig`。文件搜索在共有的 12 个文件内查找字面文本，每个命中文件返回相对路径、最多 20 行，每行最多 900 个字符。按路径读取返回至多 4,500 个字符，索引检查结果中的绝对材料目录统一替换为 `./material`。两组都限 12 次工具调用。本次只通过本地只读 MCP 接触合成材料，模型未取得仓库 shell、真实项目数据或其他会话的结果。

“显式打开文件”按模型发出的 `read(path)` 去重。搜索命中和 TypeScript 检查器内部读取另有成本。工具返回字节统计交给模型的 UTF-8 内容。输入和缓存计数来自 CLI 的 `turn.completed.usage`，累计多次推理请求，包含会话工具定义及提示词。

动态发现时，B 组读目录、查成员，直接取得目标导入和参数。恢复时它先后查了目录、搜索旧方法名、查到新方法的签名。配置任务中，两组都用精确字段名搜索后读 `config.d.mts`，这一对样本没有使用 `inspectConfig`。四份脚本都选择了 priority 的默认节点，一次运行通过。旧描述符复验得到 `control_contract_mismatch`，两份配置答案都命中了作者文件、默认值及三个约束。六次会话均未越过工具或调用数限制。

## 复核范围

模型固定为 `gpt-6.2-sol`、`low` reasoning，Codex CLI 0.170.0。每个任务使用新的 `codex exec --ephemeral --ignore-user-config` 会话。两组共用同一份同步快照，在读取工具处改变索引可见性。仓库 HEAD 为 `7ee930604`，审查中的其他改动共用该工作树；[记录](observations.json)固定了模型实际读取的两份快照 SHA-256、请求、每次工具的参数及返回长度、模型原答和 CLI token 数据。

在已构建 Host、Host Vite、Agent SDK 与 Rolldown 的工作区根执行以下命令，可在临时目录重新建立真实宿主，按相同输入运行四份脚本并核对两份配置答卷。执行依赖当前 checkout 的制品。给脚本传入一个尚不存在的输出目录时，它还会核对原实验摘要并导出两个版本的控制材料。
