# Workbench 交互设计决策

Workbench 同时服务插件管理和业务应用：管理运行、配置与依赖，或使用插件发布的功能。两者共用工作区，各自保持清楚的入口。操作说明见[工作台使用](../docs/workbench/operations.md)，状态实现见 [Frontend](FRONTEND.md)，发布边界见 [Workbench 架构](WORKBENCH.md)。

## 先确定用户任务

设计先明确正在处理的对象、下一步和需要同时参考的信息。普通浏览在当前文档继续；需要并排比较或保留另一份输入时，显式创建文档。效率看寻找、切换、滚动和重复输入的成本。紧凑界面仍须保留可辨认的名称、键盘焦点、操作入口和失败原因。

## 页面与区域怎么选

| 用户需要             | 承载方式                     | 理由                                |
| -------------------- | ---------------------------- | ----------------------------------- |
| 全局入口             | 内置入口与用户固定的应用入口 | 用户决定固定、图标或文字模式        |
| 管理插件             | 唯一插件目录 + 中央详情      | 分组、排序、多选和拖动共用目录模型  |
| 使用业务能力         | 应用路由与领域对象列表       | bot、会话等按业务 API 组织          |
| 独立阅读、编辑、比较 | 中央文档                     | 独立地址、输入、离开守卫与资源      |
| 当前插件的辅助上下文 | left/right/bottom panel      | 跟随活动文档 exact owner，包括 fork |
| 临时低频设置         | 菜单或浮层                   | 日志策略放在相应日志标题旁          |
| 多插件共用列表       | 领域聚合插件 + 来源插件 API  | Shell 无需理解各领域 schema         |

多来源列表由中心插件发布页面。各行共用中心的 publication 和会话。来源插件可以注册数据，也可以随对象提供自有编辑器的入口。用户打开来源文档后，由该来源校验和提交，中心自己的编辑仍保留在原文档。来源撤回后，中心决定如何展示最后状态。[向中心插件注册来源](../docs/workbench/composition.md#向中心插件注册来源)

## 导航和文档不变量

普通入口在活动文档导航，无活动文档才新建。活动标签后的“复制标签”按钮与菜单中的复制操作使用已提交地址与名称创建独立文档，未保存草稿归原文档。右侧“查看完整日志”打开按当前 canonical owner 筛选的独立文档，保留配置上下文。插件可通过 API 显式打开文档。

标题表达当前内容，手动重命名在刷新和重新聚焦后保留，页面身份切换才采用新名称。地址栏跟随活动文档，工具焦点不改变地址。离开、批量关闭和重置经过文档守卫；拒绝保留原布局。布局快照和业务草稿分别保存，坏快照保留供显式修复。

同一管理文档的分区使用 Mantine Tabs。标题和标签栏留在文档顶部，内容在各自的面板内滚动。选中项随已接纳的路由变化，方向键移动焦点，Enter 或空格确认切换。相关页面使用链接，刷新和保存使用有明确名称的操作控件。刷新和相关链接与对应区块标题同行。表单和列表按文档宽度决定是否并列，短窗格缩小页头间距以容纳更多内容。出站联网概览和宿主默认设置共用文档，安全审计归在认证与安全入口下。

分割线上方是系统入口，下方从应用目录开始，依次展示用户固定的入口。应用页内并列展示已固定项和完整目录，窄文档中上下排列。搜索筛选完整目录，固定列始终展示侧栏的顺序。排序、固定和插件配置控件放在行首，名称负责打开页面。配置动作聚焦或打开独立插件文档，保留应用目录的搜索和展开状态。偏好保存 canonical target、entry key 和参数路由具体 location。名称、图标、frame 与可用性从当前 publication 获取，失效入口保留偏好并标不可用。`initialShortcuts` 仅初始化缺失偏好，显式空数组保持为空。存储位置见 [Frontend](FRONTEND.md#导航和目录)。

## 工具布局的当前选择

FlexLayout Model 唯一拥有几何和标签，Worksplit 协调文档操作。中央文档支持分屏、移动与分组。官方目录和右侧官方工具固定、不可关闭，右侧内部只切换“插件信息”和“最近日志”。插件面板是独立原生 Border 标签，可关闭、重新打开和在声明区域内排序。

面板按需打开。官方扩展列表与顶部查找共用当前 owner 的声明和打开路径，重复打开聚焦已有面板；关闭后仍可从声明找回。停止插件和撤回声明的入口标为不可用。

收起保留标签，关闭移除标签并释放资源，切换 owner 释放旧资源但保留其未关闭布局。没有适用内容的区域不占位；底部无官方默认工具；左侧仅有官方目录时隐藏重复竖条。面板不改变中央地址，草稿归中央文档。放置限制、资源和恢复规则见 [Frontend](FRONTEND.md#插件上下文与面板资源)。

## 目录与批量操作

用户分组表达工作组织，依赖图、publication 分类和文档 TabGroup 分别拥有自己的含义。分组算法与保存协议见 [Plugin Catalog](PLUGIN_CATALOG.md)。

点击名称浏览，选择按钮或修饰键选择。范围选择、方向键和全选作用于当前可见展开行；保留的历史选择与本次操作范围分开。按钮、输入框和拖动手柄保持自身键盘行为。

拖动提示实际移动项、目标组和落点，复用管理器的批量移动/排序。常用操作直接可达，低频操作放菜单。滚动期间不弹悬浮提示，延迟提示补足名称与简短状态，详细诊断放详情。

## 阅读层次

先删除重复内容与空区域，再调整密度。当前位置、选择、悬停和键盘焦点应能分别辨认。尺寸、表面与交互状态由 [视觉规则](../packages/workbench/shell/color-design.md)维护。

插件信息侧栏用对齐的名称和值显示运行摘要，完整引用可复制。零依赖集中显示一条摘要，已读取且为空的扩展区域省去整块占位。读取进度、失败原因和运行异常保留在对应位置。

加载、空、失败和未报告分别呈现。运行状态依据 lifecycle 结果，批次提交只表示该批次完成提交。错误留在对应文档或区域，并给出可执行的下一步。

## 如何决定删除或放开限制

区分资源约束、交互选择和偶然实现。资源约束由其所有者执行；交互选择依据具体任务调整；无调用方的模式和失效分支可删除。

例如改变面板拖动范围时，同时明确恢复入口、owner 跟随和 Border 放置策略。原生属性控制是否可拖，策略检查 dispatch 与恢复后的落点，两者都要同步调整。界面只解释可执行操作及必要后果，内部规则由领域页维护。

## 修改与验收路径

从用户任务选择承载方式，在 [Frontend](FRONTEND.md) 找到状态所有者，检查实现与真实调用方。API 变化更新 [Workbench 架构](WORKBENCH.md)和公开用法；交互理由变化更新本页。按[验收指南](WORKBENCH_FLEXLAYOUT_VALIDATION.md)选择场景：视觉看截图，生命周期看真实发布和释放，纯文档核对事实与链接。

评审关注对象和下一步是否可发现、普通浏览是否产生多余标签、工具能否收起找回、键盘和滚动是否可控，以及分组、选择和失败是否可预测。
