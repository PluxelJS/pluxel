# 文档职责与写作

文档让新 session 能确定当前行为、找到实现并继续工作。每项规则由一个位置维护，其他入口提供简短说明和链接。

## 内容归属

| 位置                                                | 维护内容                                       |
| --------------------------------------------------- | ---------------------------------------------- |
| `AGENTS.md`                                         | 任务分流、仓库操作和完成要求                   |
| `docs/`                                             | 当前公开用法、最短完整示例、失败处理与资源释放 |
| `engineering/` 领域页                               | 内部职责、运行机制、不变量、源码和验证入口     |
| package README / `IMPLEMENTATION_INDEX.md`          | 本包职责、操作入口和目录导航                   |
| `.agents/rules/`                                    | 可复用的设计方法、理由和例外                   |
| `engineering/records/`                              | 有日期和环境范围的迁移盘点、验收证据与背景     |
| `engineering/proposals/`、`experiments/`、`spikes/` | 未完成设计、固定条件的实验与上游能力探测       |

`docs/` 按读者任务组织：getting-started、plugin-development、host、workbench、development、plugins 和 reference。框架领域页从[工程索引](README.md)定位，不复制公开教程。当前 API 由 exports、实现、测试和真实调用方共同核对；提案与旧验收记录提供背景。

## 领域页怎么写

开头直接说明该领域负责什么，以及与相邻领域的关系。正文解释主要执行路径和影响维护的规则，给出具体源码与测试入口。失败、并发、取消、保存阶段和资源所有者等会改变行为的信息应保留；非显然约束附上原因或失败例子。

用具体名称、参数、返回值和事件描述行为，优先正向直陈。减少抽象口号、免责套话、反复阅读指导和“本轮已经完成”的过程叙述。自然段解释机制；列表表达并列项或步骤；表格用于确有对应关系的矩阵。错误码和罕见语法限制放在相关参考小节，避免挤进主路径。

单次测试数量、临时日志、截图和进程状态放在变更说明中。有长期价值的环境限制与验收依据归入 records，注明观察时间与范围。已落地提案把有效规则并入领域页，只保留未决部分；已撤回的设计由 Git 保存。

## 链接与示例

- 调整路径或标题时，搜索全仓引用并修正相对链接与章节锚点；新增入口同步工程索引、相关文档导航和生成项目的 AGENTS。
- 命令使用[统一命令入口](../docs/development/workspace-toolchain.md#统一命令入口)，终端示例写完整命令。模板更新同步 README、AGENTS、安装行为和完成提示，工具版本跟随仓库基线。
- TypeScript 示例保持语法和当前导出一致，Twoslash 示例能通过类型检查。示例包含必要的失败处理与释放，省去没有独立意义的 wrapper。
- 文档整理检查内容、链接、锚点和格式；代码或行为同时变化时，再按受影响领域选择验证。
