# Shared Vault

实现：`packages/runtime/src/services/vault/VaultService.ts`

## 目标

shared vault 只有一个目的：避免敏感数据明文落盘。

## 结构

- mount 默认目录：`data/vault/global`
- `keys.age`
  用 age recipient 包装 mount DEK
- `state.enc`
  用 DEK 加密的 snapshot
- `blobs/`
  用同一个 DEK 加密的独立 blob 文件

## 存取模型

- 所有插件共享同一个 mount
- namespace 只是数据分区，不是权限模型
- `kv/docs` 进入 `state.enc`
- `blobs` 独立存文件
- 插件只看到存储面，不参与解锁和密钥管理

## 解锁模型

- `host`
  来自 `identity.json` 的 `vault.hostIdentity`
- `deploy`
  来自 `identity.json` 的 `vault.deployRecipients[]` 和环境变量私钥

管理动作只在 `ctx.root.vaultAdmin`：

- `preflight()`
- `describe()`
- `unlock()`
- `rekey()`
- `ensureHostKey()`
- `generateDeployKey()`
- `setDeployRecipients()`

规则：

- 启用 vault 的 host 在插件启动前执行 bootstrap/preflight
- mount 不存在：启动期初始化空 mount，并保持进程内已解锁
- mount 已存在但没有匹配身份：启动期 fail fast
- mount 已存在且材料错误或数据损坏：启动期抛真实错误
- 进程内一旦解锁成功，后续访问复用结果
- `describe()` 只做纯读探测，不触发解锁
- 插件侧 kv/docs/blobs 不做运行期 auto-unlock，也不会生成长期 host key

## 管理面

Vault 只有一个启用入口：显式 import `@pluxel/runtime/services/vault`。vaultAdmin 是
eager root service；host 在插件运行前调用 `ctx.prepareServices()` 后，vaultAdmin 会在自己的
`prepare()` 里完成 bootstrap。其他 host 如果启用 vault，也必须在插件运行前完成同一
service prepare。

vaultAdmin `prepare()` 内部顺序：

- `describe()`
- 仅在 mount 缺失且 host key 尚未准备时调用 `ensureHostKey()`
- `preflight()`，缺失 mount 时初始化空 mount

启动失败不做插件级消费者归因；排查用：

```sh
rg "@pluxel/runtime/services/vault|ctx\\.vault" .
```

浏览器管理面走 `/security` 对应的专用 security client。`/security` 集中做四件事：

- 看 vault 当前状态和最近错误
- 准备 host key
- 生成 deploy key 并维护 recipients
- 看 namespace / kv / docs / blobs 统计
