# Vault 加密实现约束

当前用户契约见 [Vault](../../../../docs/plugin-development/vault.md)，分层见 [Host](../../../../engineering/HOST.md)。

- 结构化 KV 是唯一 snapshot 记录模型；只接受 version 2，每条记录必须有有效 revision。
- 加密 backend 使用 age 包装共享 DEK，AES-GCM 加密 state.enc 和独立 blobs。
- KV mutation 在本实例锁内完成 copy-on-write、revision 条件检查和原子持久提交，再发布不可变 snapshot/revision；不提供跨实例 CAS 或事务。
- env/file overlay 整记录只读、不落盘；bindings-only 后端不创建密钥、文件或 Persistence 依赖。
- 部署 identity 仅接受应用显式传入的 `deployIdentity`，不读取 std-env 或 process.env。
- watch 初始快照与登记原子，通知在锁外。Owner invocation 与 root gate 覆盖接纳操作，effects 撤销订阅。
- 已有密文损坏、缺失、无法解锁时启动失败；不得按空仓库初始化。运行期间外部无效内容保留当前有效视图并报告错误，新的有效文件可恢复加载。
- 观察外部 state.enc 后解密并校验，在本实例锁内切换 snapshot 后通知；不原样回写。外部 revision 可重复或回退，watch 按内容变化通知，不以 revision 大小丢弃更新。
- `rekey()` 只原子重包 DEK，不能宣称它旋转了数据密钥。
- 备份/恢复由停机后的完整 Core FS `services/vault/` 目录 复制承担，不引入明文导出。

Host 在服务 prepare 完成后通过 `HostVaultBindings` 安装已经校验的 `envBindings` / `fileBindings`，随后才允许 Plugin admission。部署 schema 与来源映射归 Host；Vault 仅安装不可变整记录，不自行读取环境或 JSON 文件。
