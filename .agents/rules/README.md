# Agent 决策规则

本目录提供可跨项目复用的决策方法，不记录 Pluxel 当前架构事实。项目约束和现有公共契约优先于通用默认。

| 要解决的问题                                   | 入口                                                                                                                |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 设计公开 API、配置、类型、错误、扩展或生命周期 | [Library API Design](library-api-design.md)：先读硬约束，再按任务选规则与验收；包含减少猜测、类型编写反馈和组合验证 |
| 确认 Pluxel 所有权、实现边界与工程不变量       | [工程文档](../../engineering/README.md)                                                                             |
| 查询当前公开用法                               | [用户文档](../../docs/index.md)                                                                                     |
| 选择源码查询、运行中操作或回归验证工具         | [开发工具](../../docs/development/index.md)                                                                         |

新增规则前先确认它是通用决策还是项目事实。相同决策并入现有指南；不要为 coding agent 另建一份平行 API 规范。规则写清默认、原因与可观察的例外，验证用真实调用任务，不靠风格偏好。
