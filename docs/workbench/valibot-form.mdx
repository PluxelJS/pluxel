给配置字段加标题、说明、控件偏好时，使用 `valibot-form` metadata。Plugin 仍只声明一份 Valibot schema，
Workbench 会自动显示配置表单；无需为普通配置另外编写 React 页面。

## 先给一个字段加标题

```ts twoslash
import { BasePlugin, f, Plugin, v } from '@pluxel/runtime'

@Plugin()
export class ServicePlugin extends BasePlugin {
	private readonly config = this.configs.use(
		v.object({
			enabled: v.optional(v.pipe(v.boolean(), f.formMeta({ title: '启用服务' })), true),
		}),
	)
}
```

构建并运行插件，标准配置页应出现“启用服务”开关，初始值为开启。
`f.formMeta()` 只描述显示方式；字段是否必填、默认值和有效范围仍由 Valibot 决定。
保存与运行时应用的区别见[插件配置](../getting-started/configuration.md)。

当字段既有默认值又有表单 metadata 时，让 `v.optional()` 包住完成后的 `v.pipe()`：`v.optional(v.pipe(base, constraints, metadata), default)`。这样默认值属于外层可选语义，字段 extractor 解包 optional 后仍能读取内层 metadata；不要写成 `v.pipe(v.optional(base, default), metadata)`。

注意：`configs.use()` 要放在 Plugin class 的普通顶层 field；不要在 constructor 读取 config，不要使用 `#private`，每个具体 Plugin 只声明一个 object schema。

## metadata 做什么

`valibot-form` 的 core entry 不依赖 React/Mantine，适合 runtime config、CLI prompt、配置文件编辑器和 schema inspection：

```ts twoslash
import * as v from 'valibot'
import * as f from 'valibot-form'

const Config = v.object({
	mode: v.pipe(
		v.picklist(['development', 'production'] as const),
		f.formMeta({ title: '运行环境' }),
		f.picklistMeta({
			control: 'segmented',
			labels: { development: '开发', production: '生产' },
		}),
	),
})

const fields = f.extractFormFields(Config)
```

常用映射：

| Valibot schema        | metadata       | 默认 web 控件    |
| --------------------- | -------------- | ---------------- |
| `v.string()`          | `stringMeta`   | TextInput        |
| `v.number()`          | `numberMeta`   | NumberInput      |
| `v.boolean()`         | —              | Switch           |
| `v.picklist()`        | `picklistMeta` | Select           |
| `v.array()`           | `arrayMeta`    | List             |
| `v.record()`          | `recordMeta`   | Table            |
| `v.object()`          | `objectMeta`   | Card/stack       |
| `v.variant()` / union | `unionMeta`    | Select/segmented |

### 类型入口

类型直接从 package 源码导出。下面的示例由 Twoslash 对当前 workspace 类型检查，不在文档中维护另一份类型声明：

```ts twoslash
import type { FormMeta, ObjectLikeSchema } from 'valibot-form'
import type { AutoFormProps } from 'valibot-form/web'

type MetadataKeys = keyof FormMeta
//   ^?

type FormProps = keyof AutoFormProps<ObjectLikeSchema>
//   ^?
```

`formMeta()` 的 `title` / `description` 使用 Valibot 标准 metadata，help、section、layout、disabled、readOnly 和 hidden
仍是表单展示偏好；类型对应的 `*Meta()` 只负责控件偏好。requiredness、选项、格式和范围仍来自 Valibot schema，例如
`v.optional()`、`v.url()`、`v.minValue()`、`v.maxValue()` 和 `v.integer()`。原生 `v.title()`、`v.description()` 与
`v.metadata({ title, description })` 也会按 pipe 顺序互操作，但标准示例使用一次 `formMeta()` 集中声明。

需要编辑 schema 或查看类型补全时，打开独立的[配置 Playground](./configuration-playground.md)。

## Web adapter

只有在自己的 React 应用中需要自动表单，才从 `valibot-form/web` 导入。标准 Workbench 配置页已包含它。
独立应用需要安装 React、Mantine、TanStack Form、Tabler Icons 和 dnd-kit：

```sh package-install
npx nypm add valibot-form valibot react react-dom @mantine/core @mantine/hooks @tanstack/react-form @tabler/icons-react @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities
```

```tsx twoslash
import { MantineProvider } from '@mantine/core'
import '@mantine/core/styles.css'
import * as v from 'valibot'
import { AutoForm } from 'valibot-form/web'

const Config = v.object({
	mode: v.picklist(['development', 'production']),
})

async function saveConfig(_value: v.InferOutput<typeof Config>) {}

// ---cut---

export function ConfigEditor() {
	return (
		<MantineProvider>
			<AutoForm
				schema={Config}
				formOpts={{
					defaultValues: { mode: 'development' },
					onSubmit: async ({ value }) => saveConfig(value),
				}}
			>
				<AutoForm.Fields />
				<AutoForm.Actions>
					{({ submit, reset, dirty, canSubmit, submitting }) => (
						<div>
							<button type="button" onClick={() => reset()} disabled={!dirty || submitting}>
								重置
							</button>
							<button type="button" onClick={submit} disabled={!canSubmit || submitting}>
								保存
							</button>
						</div>
					)}
				</AutoForm.Actions>
			</AutoForm>
		</MantineProvider>
	)
}
```

上例是独立 React 应用，因此自行导入 Mantine CSS。放进 Workbench View 时，仍需自己的 `MantineProvider`，
但应删除 `@mantine/core/styles.css` 导入，基础 CSS 已由宿主加载；见[页面资源参考](./renderer-resources.md)。

`AutoForm` 负责根据 schema metadata 规划和渲染字段；配置 authority 仍然是 runtime 的 `configs.use()` 校验流程。把表单值送回 host API 前，服务端必须再次用同一个 schema 校验，不能把浏览器表单当作信任边界。

### 嵌套编辑与错误反馈

Object、数组行和当前 Union 分支中的可编辑字段使用完整的 TanStack 字段路径，例如
`database.host`、`servers[0].host`。各字段独立记录 blur 和错误；数组删除、重排使用 TanStack 的数组操作，
交互状态随行移动，受影响的校验错误重新校验或清除。

Workbench 的配置保存和 Content action 会把服务端错误放到对应的已显示字段；隐藏字段、未激活分支、
无法准确定位的路径错误保留在表单摘要。编辑字段会清除该字段的旧服务端错误和表单摘要，
其他字段的错误继续显示；开始下一次提交时清除上一轮服务端错误。修改后可保留草稿再次提交。
请求期间继续编辑时，迟到响应不会覆盖新草稿或给新值挂上旧校验错误；配置保存成功仍会更新已保存基线，
新草稿保留为未保存修改。Content action 有新草稿时也不会自动清空或关闭表单；操作反馈仍报告已提交请求的结果。

独立使用 `AutoForm` 时，
`form.setErrorMap({ onServer: { fields: { 'database.host': '地址不可用' } } })` 可设置字段错误；
编辑该字段会清除它的旧服务端错误。跨字段错误与表单摘要的失效策略由调用方决定。

`reset()` 同时重置表单和局部编辑草稿，包括 Union 的非激活分支缓存、数组与 Record 的新增草稿。
在提交回调中调用 `formApi.reset()` 具有相同效果。切换字段计划时，使用 `resetKey` 明确开始新的编辑会话。

Record 内无法被路径准确表示的字面量 key（如 `x.y`、`0` 或空字符串）保持原样，通过可绑定的祖先字段编辑；
这类值没有独立的 TanStack 字段路径，Workbench 将相应服务端错误显示在摘要。
如果顶层 key 本身无法被 TanStack 路径准确表示，则显示只读说明并保留原值，避免写入错误位置。
需要编辑这类数据时，将它放在普通命名的 Record 或 Object 字段内。

传入 `schema` 用于字段规划和默认值，不会自动安装客户端 validator 或将编辑值转换成 schema output。
独立表单可通过 `formOpts.validators` 显式选择客户端校验时机；Workbench 的 portable 字段计划仍由服务端执行完整校验。

## 与 Pluxel 配置界面的边界

`valibot-form` 提供 schema metadata、字段提取和可选 Web adapter，不提供 Pluxel Plugin 发现、配置传输或持久化 API。自定义配置界面应直接接收 browser-safe 的 schema，并通过应用自己的服务端接口提交修改；服务端继续使用同一 schema 校验输入。

Pluxel Workbench 内置的 Plugin 配置页由宿主读取 runtime config metadata。Plugin 作者只声明 `this.configs.use(Config)`，不调用 Workbench 内部的 schema projection 或配置 patch 实现。

## 检查清单

- schema 是 object 或 intersect，适合 `AutoForm`。
- 默认值写在 `v.optional(v.pipe(...metadata), default)`，没有业务 fallback，也不会在解包 optional 时丢失 metadata。
- `configs.use()` 是 class 顶层普通 field，且 Plugin 只有一个 config field。
- server runtime 是最终校验者；browser 表单只提供编辑体验。
- core 工具需要 schema 时只 import `valibot-form`，不把 React/Mantine 带入 server bundle。
