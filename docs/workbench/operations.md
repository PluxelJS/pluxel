Workbench 提供了类似于现代 IDE 的可定制工作区环境。你可以在其中分屏查看不同插件、固定常用业务应用、实时查看结构化日志流，并在插件发生故障时快速定位原因。

## 窗口与布局管理

### 查找与打开入口

- **左侧入口栏**：快速切换业务应用目录、插件管理目录、全局日志与依赖图；
- **命令面板（`Ctrl/⌘ + K`，`Ctrl/⌘ + P` 同样可用）**：搜索页面、插件和面板，也能执行显示或收起面板、关闭文档、恢复默认布局、切换明暗主题等工作区命令；↑/↓ 在结果间移动，Enter 执行所选项，不可用的命令显示为禁用；
- **首页“需要关注”**：列出运行异常、依赖阻塞、装配问题、不可用和等待启动的插件及原因，并显示最近一次失败或未生效的运行更新；读取失败时可直接重试；
- **分屏与拖拽**：中央文档标签支持自由拖拽分屏、固定（Pin）与多标签分组，便于同时比对配置与业务页面。

<span id="固定常用应用"></span>

### 固定常用应用

左侧入口栏分割线下的第一项是“应用”。“全部应用”沿用插件目录的分组和排序，可按组名、应用名称、所属插件或路径查找页面。点击名称前的图钉即可固定到侧栏。命令面板中的应用搜索结果也可以固定。

应用行首的配置按钮打开所属插件的配置标签页。切回应用页可以继续当前搜索，重复打开同一插件会聚焦已有配置标签页。

“已固定到侧栏”列显示当前的完整顺序。拖动行首手柄可调整顺序，点击手柄旁的图钉可取消固定，包括已经不可用的页面。用键盘排序时，聚焦手柄，按空格键提起，用上下方向键移动，再按空格键放下。固定状态与顺序在重新打开工作台时保留。

### 常用快捷键速查

| 快捷键                          | 功能说明                         |
| ------------------------------- | -------------------------------- |
| `Ctrl / ⌘ + K` / `Ctrl / ⌘ + P` | 打开命令面板：查找入口或执行命令 |
| `Ctrl / ⌘ + B`                  | 展开或收起左侧边栏               |
| `Ctrl / ⌘ + W`                  | 关闭当前选中的文档标签           |
| `Ctrl / ⌘ + S`                  | 保存当前选中的配置分区           |
| `F2`                            | 重命名当前标签页的自定义显示名称 |

## 生命周期与故障排查

当插件在界面中显示为异常或未就绪时，可按照以下步骤快速定位：

### 1. 检查插件状态与依赖拓扑

- 在插件管理列表中，绿色圆点表示处于正常 `running` 状态；灰色表示处于停止状态；红色表示启动失败（`start-failed`）；
- 如果插件显示为被阻塞（`dependency-blocked`），点击展开右侧“插件信息”，查看是哪一项依赖未启动或失败。

自动启动和依赖选择显示当前节点采用的优先级、来源及写权限。批量修改自动启动后，可在通知中恢复原保存值。之前由代码或默认值决定的节点会恢复继承。若另一客户端随后修改了策略，恢复会报告版本冲突。

首页的“宿主执行参数”可以保存默认启动期限、排空期限及并发预算，留空恢复继承。界面同时显示当前采用的值和重建宿主后生效的值。

### 2. 检查配置是否合法

- 如果修改配置后报错，查看字段下方的验证提示，确认输入类型、数字范围或 URL 格式是否符合 Schema 要求；
- 如果配置已保存但行为未变，确认插件是否注册了 `configs.onUpdate()` 动态热应用；若未注册，需手动点击插件卡片右上角的“重启”按钮加载新配置。

### 3. 查看实时日志流

- 打开右侧抽屉中的“最近日志”标签，或点击最左侧导航栏中的“日志”页面；
- 支持按插件名称或日志级别（`error`、`warn`、`info`）进行精准过滤，展开日志条目可查看完整的结构化属性与异常堆栈。

## 查看受管出站 HTTP

左侧的 **受管出站 HTTP** 实时显示最近联网记录，并列出本次宿主运行中已记录过受管请求的插件节点。每行显示最近请求时间、目标 origin、结果和响应、失败、拒绝的计数。收到新记录时，节点列表随之更新。

从列表打开 **联网记录**，总览和最近记录会筛到对应节点。**出站设置** 打开该节点的配置，配置页的 **本节点联网记录** 返回同一个筛选。规则、记录和跳转使用包含 fork 的完整节点地址。

**完整联网日志** 打开现有日志阅读器中的受管出站流，并保留节点筛选。流保留本次宿主运行最近 5,000 条记录，包括方法、目标 origin、响应或失败结果和耗时。页面顶部的 **宿主默认设置** 用于编辑宿主策略。

在插件详情的 **出站 HTTP** 编辑节点覆盖。每个字段旁显示宿主当前采用的值，输入框编辑保存规则。插件发出第一笔请求前也可以配置。

有管理权限的操作者可以编辑允许访问的 origin、超时与默认请求头，或清除节点覆盖以恢复继承。宿主支持并开放代理配置时，可继承、清除受管代理或填写无凭据的 HTTP(S) 代理地址。新请求采用已应用设置，代理连通性由真实请求结果报告。

页面覆盖经 `ctx.wretch` 或 `ctx.fetch` 进入受管传输的请求。直接使用全局 Fetch、其他 HTTP 客户端或套接字的请求有各自的传输路径。 [宿主出站配置](../host/configuration.md#受管出站-http)

宿主声明 `records: 'summary'` 时，页面在打开或刷新时读取联网节点摘要。声明 `records: 'off'` 时，页面显示记录已关闭，出站设置继续可用。声明 `managed: false` 时，页面显示传输由宿主部署声明决定。
