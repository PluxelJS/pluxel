---
title: 插件开发检查清单
description: 在提交插件代码前，核对依赖声明、配置 Schema、资源释放与单元测试。
---

在提交插件代码或发起 Pull Request 前，建议对照以下关键项进行快速自查：

## 1. 依赖与生命周期
- [ ] 必需依赖是否已在构造函数中以强类型参数声明，且对应的提供方包已添加到 `package.json` 的依赖中？
- [ ] 在 `init()` 阶段创建的外部资源（定时器、外部监听、Worker 任务）是否均已通过 `this.ctx.effects.defer()` 登记了清理逻辑？
- [ ] 插件在经历停止或重启后，是否能够干净退出且无悬挂的后台 Promise？

## 2. 配置与校验
- [ ] 配置 Schema 是否使用了 Valibot 的标准对象结构（`v.object(...)`），且默认值均已在 Schema 中明确给出？
- [ ] 若支持运行时免重启配置热更新，是否已在 `init()` 中注册了 `this.configs.onUpdate()` 并在回调中正确更新了运行时变量？
- [ ] 插件内部是否避免了在常规配置中硬编码数据库密码或 API 密钥（应转为使用 [Vault](./vault.md)）？

## 3. 日志与错误处理
- [ ] 记录错误日志时，是否将捕获到的原始 `Error` 对象放入结构化字段中以便追溯堆栈？
- [ ] 带有高开销计算的调试日志是否使用了 `lazy()` 延迟求值？
- [ ] 对外暴露的方法在遇到可恢复的业务异常时，是否返回了清晰的错误类型或 `Result` 结构？

## 4. 自动化测试
- [ ] 是否编写了基于 `@pluxel/test` 的自动化测试，验证插件在测试宿主中的启动、方法调用与停止行为？
- [ ] 在终端运行 `vp run verify` 或 `pnpm test`，确认所有单元测试均能通过。
