## Preserve native PostgreSQL and PGlite configuration and resource ownership

`postgres()` now accepts `pg.PoolConfig` or a native `Pool`; `pglite()` accepts
`PGliteOptions` or a native `PGlite` instance. Native defaults and options remain
available, including TLS certificates, password callbacks, pool configuration,
PGlite extensions, filesystems and initialization settings. Replace the former
`pool.max`, renamed timeout fields and `tls` mode with native `max`,
`idleTimeoutMillis`, `connectionTimeoutMillis` and `ssl`. Import configuration
types from the driver instead of `PostgresOptions` or `PgliteOptions`.

Configuration-created resources remain lazy and Host-owned. Passed instances
are borrowed: Host shutdown drains accepted work and removes its own pool error
listener without closing the application-owned resource. PostgreSQL scheduling
uses the actual pool limit; PGlite remains serial. Managed owner isolation and
migrations keep the same lifecycle.
