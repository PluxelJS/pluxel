# Typst Studio workspace

This directory is the complete project. Edit its ordinary files; Studio detects saved changes. `studio.json` declares only the project name and font directories (workspace-relative). A report is discovered at `folder/folder.ts`; that module must default-export `defineTypstDocument({ template, schema, createFiles? })` imported from `@pluxel/typst/template`. The entry filename supplies its name; `template` is a relative `.typ` path resolved from its directory and `createFiles` is synchronous. Do not add document registrations to studio.json. Shared themes and fonts live under `共享/` and can be reused by any document through normal Typst imports.

Keep a report to its entry and `.typ` source; inline schema in the definition unless it is actually shared. Prefer native Valibot titles and descriptions so the document has no form-renderer dependency. The schema validates caller data regardless of whether it comes from a form, API, database, or batch job.

For document or form changes, read `.agents/skills/typst-authoring/SKILL.md`. Form values come from external caller input, are stored outside this workspace by Studio, and become virtual /inputs files at compile time. Use Valibot defaults for demonstration values; do not create data.json files for form state. Preserve static assets and unrelated documents. Changing a shared theme affects its importers, so check the affected documents. Studio's `compile_preview` tool requires an explicit input selection: `{ entry, input: { kind: 'stored' } }` uses saved form values; `{ entry, input: { kind: 'data', data: {} } }` uses defaults or supplied data. Follow with `read_preview_pages` using its revision, and `export_pdf` for a ready PDF artifact. External coding agents use the running app's `@report-template-studio/app/client` exports `discoverStudio` and `withStudio`: explicitly select instance and project, then `compile({ projectId, entry, data })`, `renderPage` and `exportPdf`. Use the returned PNG path with your image viewer. See the app README's program integration example; do not create a temporary bridge, new backend per compile or connection files in this workspace. If no Studio is available, report the missing validation boundary; a plain Typst CLI does not validate the report schema/createFiles contract.

TypeScript report entry code runs through Vite inside a restricted runtime with `valibot` and `valibot-form`; Node, network, and filesystem APIs are unavailable there. The coding agent edits normal files, but the document runtime receives only this workspace. Put reusable document logic in workspace modules.
